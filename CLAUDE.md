# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

This repository contains OpenTofu modules exported from providers. Each module wraps a single provider resource type using a `for_each` pattern, allowing users to bring their own `terragrunt.hcl` or `*.tfvars` files.

## Module Structure

Every module lives in its own directory and consists of exactly four files:

- **`main.tf`** — One resource block using `for_each = var.<resource_type_plural>`; all attributes mapped via `each.value.<attr>`
- **`variables.tf`** — A single `map(object(...))` variable named after the resource type (plural); required attributes use bare types, optional attributes use `optional(type)`
- **`outputs.tf`** — A single output exposing the entire resource map
- **`versions.tf`** — Provider version constraint for the module

## Conventions

**Variable naming:** The variable and output names are the pluralised resource type (e.g., `azurerm_resource_group` → `resource_groups`).

**Type mapping for variables.tf:**
- Required, non-computed attributes → bare type (e.g., `string`, `set(string)`)
- Optional or computed attributes → `optional(type)` (e.g., `optional(string)`, `optional(map(string))`)

**`=` sign alignment:** Attribute names within each `object({...})` block are padded so all `=` signs align, computed across all attributes and block types at the same nesting level.

**Description block in variables.tf** uses a heredoc listing Required and Optional attributes separately:
```hcl
description = <<EOT
Map of resource_groups, attributes below
Required:
    - location
    - name
Optional:
    - managed_by
    - tags
EOT
```

**versions.tf** uses a pessimistic constraint (`~>`) locked to `major.minor` (e.g., `~> 4.61`).

## Directory Layout

```
current-examples/        # Hand-crafted reference modules
  azurerm_resource_group/
  azurerm_management_group/

opentofu/                # Auto-generated modules
  <provider>/            # e.g. azurerm
    <version>/           # e.g. 4.61.0
      module_<resource>/ # e.g. module_azurerm_resource_group

scripts/
  generate.py            # Generation script
  providers.json         # Provider list and config
```

## Automation

Modules are auto-generated by `scripts/generate.py` using **OpenTofu** (`tofu`):

1. Querying `registry.terraform.io` for the latest provider version
2. Using `tofu providers schema -json` to extract resource schemas
3. Generating the four module files for every resource type
4. Writing output under `opentofu/<provider>/<version>/module_<resource_type>/`

Configuration is driven by `scripts/providers.json`.

### Running locally

```bash
# All providers in providers.json
python scripts/generate.py

# Single provider
python scripts/generate.py azurerm

# Pinned version
python scripts/generate.py aws --version 6.33.0

# Overwrite existing modules
python scripts/generate.py azurerm --force
```

Existing modules (all 4 files present) are skipped automatically.
